## 二、问题清单（ISS-UJ 系列）

### ISS-UJ-03 · P1 · 确认明细时用户编辑的扣费行被静默丢弃
- **现象**：在扣费表格把两行改为700元（UI实时显示合计1400/应退2480）→ 点「✔确认明细」→ Toast成功 → DB落库仍为分析提取的原值200+100=300、退款3580。
- **根因**：`useWorkflow.js handleSaveAndConfirm()` 的 fee-confirm 请求体只含 contract_fields/clauses 等，**未携带 `deductions` 数组**；后端 app.py:836 回退取工单旧 deduction_detail。
- **影响**：金额口径主链路的数据完整性——用户以为按修改后金额确认，实际按旧值归档并写入回复函口径。
- **修复建议**：payload 增加 `deductions: ar.value.deductions`（后端已支持该字段）。

### ISS-UJ-02 · P2（建议升P1评估）· 合同分析失败时用户被完全卡死
- **现象**：AI分析失败（文本不足/LLM超时）后，`ar=null` → 扣费表格、"添加行"、"确认明细"全部不渲染，无手动兜底录入路径；归档闸门因此永远无法满足。
- **根因**：`templates/index.html:741` 整个编辑区 `<template v-if="ar">`；本地规则解析虽产出draft（job result里有contract_fields）但整体failed不展示。
- **建议**：分析失败时提供"手动录入费用方案"降级入口（复用同一表格组件绑定空deductions即可）。

### ISS-UJ-05 · P2 · 费用确认后工作台闸门状态不同步
- **现象**：fee-confirm 成功后归档区仍显示"扣费明细表未确认"、按钮禁用；必须退出案件重新从列表进入才恢复。
- **根因**：闸门读 `selectedTicket.fee_plan_status`（列表装载时的快照），confirm 只更新了 `ar.fee_plan_status`，未回写 selectedTicket。

### ISS-UJ-06 · P2 · SPA内列表数据陈旧
- **现象**：费用已确认的案件在列表页仍显示"¥0 未核算"，刷新页面后才显示"¥3,580 ✓费用已确认"。与UJ-05同根源（跨组件状态同步依赖整页刷新）。

### ISS-UJ-04 · P2 · "✓ 登记时生成"静态文案失实 + 登记表功能无入口
- **现象**：归档路径预览固定显示"投诉登记表.docx ✓ 登记时生成"，但 registration_form_path 全库159条中仅1条非空；`genRegistrationForm`/`/api/tickets/<id>/register-form` 存在却未绑定任何按钮。
- **连带风险**：若两件套都缺失，归档会被"无可归档文件"拒绝（本次因回复函存在而通过）。Toast文案需同步修正（见UJ-07）。

### ISS-UJ-07 · P2 · 归档成功Toast文案与事实不符
- **现象**：Toast"归档成功已生成登记表与回复函两件套"，实际归档目录仅含回复函一件（登记表从未生成）。
- **建议**：按实际复制的文件动态生成文案。

### ISS-UJ-01 · P2 · 三系统未命中时无法补全学员姓名
- **现象**：查无此人建案后，姓名永久为空（列表显示"— （未归属）"、归档路径"未知"）；工作台档案区只读，无补录入口。
- **建议**：档案卡增加"手动补录姓名/网点"小入口（写 student_name/school_short 即可）。

### ISS-UJ-08 · P2 · 新增投诉页粘贴的投诉描述未落库
- **现象**：在①粘贴区输入完整投诉描述后建案，complaint_content 为空串。粘贴区似乎只服务于证件号/手机号提取，正文内容用户会预期被保存。
- **建议**：建案时将非证件号文本段写入 complaint_content，或在②区提供独立的"投诉内容"字段。
