# 黄金样本验收表（上传合同扣费）

**Status:** 待用户填写期望值 → 主 Agent 跑管线出差异表
**用途：** 把"扣费金额算错""识别没做好"这类模糊反馈，变成逐项可判定的对/错。
**样本来源：** `纸质合同样板/` 下三个真实案例（已确认存在）
**规则：** 期望值必须由经办人**人工手算**得出，不受系统输出影响（避免锚定偏差）。
填完这张表 → 我跑一次管线 → 出「系统输出 vs 期望值」差异表 → 按偏差性质分流修。

## 附：审计中发现的待确认项（需你拍板，不止于金额）

### 1. 合同金额异常时的提示口径

当前 `extract_contract_fees` 只有**一条**告警规则：服务费合计 ≠ 拆分明细
（`contract_service.py:622-627`）。以下情况**目前不会提示**：

| 情形 | 当前行为 | 你期望的行为 |
|---|---|---|
| 培训费总额抽不到（空白/OCR 失败） | 静默按 0 参与计算 | ________ |
| 合同总额与各项之和差距过大 | 无提示 | ________ |
| 考试费/工本费为 0 但合同有该科目 | 无提示 | ________ |
| 实操单价缺失 | 该项标 pending，不计入合计 | ________ |

### 2. 错漏降级策略是否符合预期

当前策略（`upload_pipeline.py:278-289`）：一旦检出任何 warnings，**所有**扣费项
金额清零 + 标 pending + `refund=0`，等人工逐项填。

替代方案：**只降级受影响的项**，其余项照常按档位算。请确认要哪种。

### 3. 三条样板工单的库内现状（供参考）

`training_hours` 为空、`contract_set` 份数为 0 —— 即**尚未走通完整流程**。
