# 诊断报告：上传合同「识别差 + 扣费金额错」

**Status:** ready-for-agent — 两个根因已实测复现，证据齐全
**日期：** 2026-09-03
**样本：** `纸质合同样板/罗炳灿-2023版/`（罗炳灿，110101199003070011，2023-05-17 报名，栅B 桥头东江分校，C2）
**复现命令：** `env -u PYTHONPATH ./venv/bin/python3 tmp/run_golden_baseline.py "纸质合同样板/罗炳灿-2023版" "2023-05-17" "分校"`

---

## 结论先行

不是「功能没做完」，而是**两层静默降级叠加**，且每一层都不告知用户：

> 视觉模型额度耗尽 → 静默回退本地 EasyOCR（质量差）
> → OCR 把违约金条款读成 10% → 档位识别按该句命中判为 `2021_2022`
> → 用 10% 违约金率 + 2021 版必扣项去算 2023 版合同 → 金额系统性算错
> → 全程 UI 报「confidence: high」，无任何告警

```
⚠️ 第2页识别失败: 同上
[VISION] 识别完成: 0/2 页成功

```

- 配置：`data/config.json` 的 `llm_contract_vision` 三项全空 → `config.py:32` 兜底到 `llm` 段，
  实际用 **通用文本模型 `qwen3.7-plus`** 当视觉模型。
- `paddle` 未安装（只有 `paddleocr` 包，缺 `paddle` 运行时）→ `contract_service.py:96-98`
  直接走 EasyOCR。
- 最终 `text_source = "local_ocr"`，正文 4121 字，但质量明显不合格。

`identify_tier` 也不知道自己拿到的是 OCR 文本还是视觉文本 → 见根因 B。

## 根因 B：档位识别把 2023 版判成 2021-2022（违约金率 10% vs 20%）

### 证据

实测打分（`tmp/run_golden_baseline.py` 输出 + 逐条特征核对）：

```
候选（2023 + 分校）= ['2019_service','2019_pay_agent','2019_training','2021_2022','2023_branch_school','2019_dongcheng']

各档打分：
  2021_2022          score=3   ← 命中「违约金为全部培训费用的10%」(w=3)
  2023_branch_school score=0   ← 四条特征句全部未命中
  其余               score=0

识别结果：tier_id=2021_2022  confidence=high  score=3
```

`2023_branch_school` 四条特征句在该 OCR 文本中**全部缺失**：

| 特征句 | 权重 | 命中 | 模板中是否存在 |
|---|---|---|---|
| 全部培训费用的20%作为违约金 | 3 | 缺失 | ✅ 存在于 `1合同种类/2023年/...（分校）.docx` |
| （必扣项） | 2 | 缺失 | ✅ 存在 |
| 建档费 | 2 | 缺失 | ✅ 存在 |
| 包含乙方理论培训、实操培训及甲方协助乙方建档、学员IC卡等相关服务费 | 2 | 缺失 | ✅ 存在 |

**特征句配置本身是对的**——我已用 2023 分校模板 docx 逐条核验通过。
问题在于 OCR 文本质量不足以让它们命中。

### 致命点：单点数字决定档位

`2021_2022` 的特征句是「违约金为全部培训费用的**10%**」，
`2023_branch_school` 的是「全部培训费用的**20%**作为违约金」。
两者互斥，且**只差一个字符**。OCR 把这处数字读错，档位立刻翻转。

OCR 文本中这句话的实际情况（本次实测原文）：

```
2、违约金为全部培训费用的10%，乙方因不可抗拒因素而退学的，甲方不收取违约金。
```

而同一份 OCR 文本的另一处却读到了 20%：

```
（1）实行预约培训的，如乙方在公安部门受理前退学的，甲方扣减乙方已交理论培训费及相关服务费的20%的违约金后
```

即：合同上 10% 与 20% 并存（分不同条款），且 `data/contract_templates.yaml:222` 已注明
「模板默认 10%，但可能有手写修改（如罗炳灿案手写 20%）」——**OCR 读不到手写修改**。

### 连锁后果

判成 `2021_2022` 而非 `2023_branch_school` 直接导致：

| 项目 | 2021_2022（错） | 2023_branch_school（对） |
|---|---|---|
| 违约金率 | 10% | 20% |
| 必扣项清单 | 2021 版 | 2023 版（含建档费等） |
| 分店场地费 +700 | 不适用 | 不适用（分校无此项） |

以培训费 3980 元计，仅违约金一项就差 **398 元**。

## 根因 C（隐蔽）：冲突检测形同虚设

`contract_tiers.py:342-348` 的冲突检测遍历 `tier["required_features"]`，
但 7 档里有 6 档的 `required_features` 是**空列表**：

```
2019_service           required=0
2019_pay_agent         required=0
2019_training          required=0
2021_2022              required=0   ← 本次判错的档位，无必含特征可校验
2023_branch_school     required=0
2023_branch_store      required=1
2019_dongcheng         required=0
```

循环空转 → 不产生任何 conflict → `confidence` 保持 `high`（`contract_tiers.py:363`
的降级分支根本没被触发）→ **用户看到「高置信度」，实际是错档**。

## 根因 D（用户明确要求，尚未实现）：金额异常不提示

`extract_contract_fees` 目前只有**一条**告警规则（`contract_service.py:622-627`）：
协助报考服务费合计 ≠ 拆分明细。

本次样本中该规则**正常触发**（`460 ≠ 300+130+130=560`），但以下情形**完全不提示**：

| 情形 | 现状 |
|---|---|
| 培训费总额抽不到（空白 / OCR 失败） | 静默按 0 参与计算 |
| 合同总额与各项之和差距过大 | 无提示 |
| 考试费为 0 但合同载明该科目 | 无提示 |
| 实操单价缺失 | 该项标 pending，但无显式提示文案 |

另注：本次样本中合同「理论培训费及相关手续费人民币____元」处**是空白**，
但系统照样抽出了 `theory_fee = 1650.0`——该数值来源可疑，需人工核对真伪。

## 修复建议（按优先级，每项均需回归测试）

| 级别 | 修复项 | 位置 |
|---|---|---|
| P0-1 | 视觉识别失败 / 回退本地 OCR 时，**必须**把 `text_source=local_ocr` 与降级警告返回给前端并在预览页顶部显式提示 | `contract_service.py:236-249` |
| P0-2 | `text_source` 不是 `pdf_text`/`vision_text` 时，档位识别 confidence **强制降为 low**，要求用户手选档位，禁止自动定档 | `contract_tiers.py:320-330` |
| P0-3 | 补齐 7 档 `required_features`（除 `2023_branch_store` 外全为空），让冲突检测真正生效 | `contract_tiers.py` 档位表 |
| P0-4 | 档位特征句**移除违约金率数字**（10%/20%），改由结构特征定档；违约金率单独抽取并与档位默认值交叉校验（ADR-0001 原意，实现走偏） | `contract_tiers.py` + `anchor_resolver.py` |
| P1-1 | 金额异常提示：总额抽不到 / 总额与分项之和偏差过大 / 考试费缺失 → 显式告警 | `contract_service.py:573-644` |
| P1-2 | 错漏降级改为「只降级受影响项」，而非全部清零（当前 `upload_pipeline.py:278-289`） | `upload_pipeline.py` |
| P2 | 安装 `paddle` 运行时，或改用 `pypdfium2` + 更适合的中文 OCR 后端 | 环境 |
