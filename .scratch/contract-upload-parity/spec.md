# 规格：上传合同对齐「下载合同并分析」全链路能力

Status: ready-for-agent
来源：grill-with-docs 共识（2026-08-31，见 `CONTEXT.md`、`docs/adr/0001`、`docs/adr/0002`、`demo/contract-upload-parity-v1.html`）

## Problem Statement

学员没有在东莞驾培系统上留有电子合同时（2017–2022 年的纸本合同学员为主），经办人只能手动上传合同照片。当前上传支路只做了「存文件 + 压缩 + 合并」，与下载链路相比缺了四件事：不能自动提取合同文本、不能预览原文、不能按学员进度自动计算扣费明细、更不能把扣费明细定位并高亮到合同原文上。经办人只能对着照片肉眼找条款、手算应退金额，慢且容易错——而纸本合同学员恰恰是退费争议最多的群体。

更隐蔽的问题：系统内没有任何「合同档位」概念，而六档合同的违约金率差三档（0%/10%/20%）、2023 分店比分校多扣 700 元场地费。目前违约金率全靠 LLM 从 OCR 文本里抽，抽错就是几千元的应退差额。

## Solution

上传合同后，系统对**每份**上传文件自动完成：提取文本 → 识别合同档位（用报名日期 + 网点类型推断，特征句校验，用户可改）→ 抽取关键字段与扣费锚点 → 按档位规则 + 学员进度自动计算扣费明细 → 把每条明细用字符偏移量锚定到结构化原文。

经办人看到一个三栏预览：左侧结构化原文（带条款号）、中间原件影像（可折叠）、右侧扣费明细（点一条，左侧高亮原文、中间对应页闪烁）。顶部摘要条显示培训费总额、已缴、必扣、依实、违约金与应退，金额按置信度着色；有「待确认」项时不允许确认费用方案、不允许归档。

一次上传多份（2019 年常见 2–3 份并行合同）时按「一套合同」处理：各份独立分析，明细汇总，培训费总额为各份之和。

## User Stories

1. 作为经办人，我想一次上传多张合同照片（或多页 PDF），系统自动把它们归类为「一套合同」中的各份（服务/代缴/培训），所以我不需要手动建多条记录。
2. 作为经办人，我想让系统自动识别每份合同属于哪个档位，所以我不必熟记六个版本的扣费差异。
3. 作为经办人，我想看到档位识别的置信度和依据（报名日期、网点类型、命中的特征句），所以我能判断该不该信它。
4. 作为经办人，当识别结果不对时，我想在下拉框里直接改档位并让扣费立即按新档位重算，所以纠错只需一步。
5. 作为经办人，我想在左侧看到带条款号的结构化合同原文，所以我能像看文本一样快速浏览纸本合同。
6. 作为经办人，我想在中间看到原件影像（照片/原 PDF），所以 OCR 认错金额时我能翻原件核对。
7. 作为经办人，我想让原件面板可折叠成缩略图条，所以长合同时左侧原文有更多空间。
8. 作为经办人，我想点击右侧任一条扣费明细，左侧自动滚动并高亮对应原文片段、中间对应页闪烁，所以我能指着合同向投诉人解释每一笔扣费。
9. 作为经办人，我想让必扣项（服务费/建档费/IC卡/场地费等）按档位自动列出，所以不用手工抄退费表。
10. 作为经办人，我想让考试费只按学员已考/已约考的科目计算，所以没考的科目不会被凭空扣钱。
11. 作为经办人，我想让实操培训费按第三系统审核学时 × 合同单价自动计算并封顶校验，所以最贵的一项不用手算。
12. 作为经办人，我想让违约金按档位默认比例（0%/10%/20%）计算，而不是赌 OCR 认没认对那个百分号，所以金额不会因一个错字差几千。
13. 作为经办人，当 OCR 从合同抽到的违约金率/考试费与档位默认值冲突时，我想看到告警提示，所以我知道这份合同可能有特殊约定需要人工核对。
14. 作为经办人，合同里手写的金额（培训费总额、实操单价）OCR 没认出来时，我想看到该项标为「待确认」且不计入应退，所以不会拿一个编造的数字去谈退费。
15. 作为经办人，存在「待确认」项时我想让系统拒绝确认费用方案和归档，所以不会把半成品结论归档了事。
16. 作为经办人，我想让金额按置信度着色（档位默认=绿、OCR 抽取=琥珀、人工录入=绿实心、缺失=灰），所以一眼知道哪些数字可以直接用。
17. 作为经办人，2019 年学员只传了 2 份合同（没有服务合同）时，我想让系统按这 2 份汇总并在摘要条标注「已识别 2 份」，所以不写死三份也能算。
18. 作为经办人，我想让已缴金额以我人工录入的为准、OCR 抽到的应收总额只做交叉校验，所以投诉人报的实缴数是权威。
19. 作为经办人，学员进度更新后（新考了一科/学时增加）我想让扣费自动重算，所以不用删掉重传。
20. 作为经办人，重复打开同一份合同的预览时我想秒开，所以分析结果、正文和锚点都已缓存，不重复跑 OCR。
21. 作为经办人，我上传的扫描版 PDF 合同也想有页图可翻，所以中间面板对三种原件类型（照片/文本 PDF/扫描 PDF）行为一致。
22. 作为经办人，下载件学员（有驾培电子合同）的现有流程我想完全不受影响，所以新功能上线不引入回归。

## Implementation Decisions

- **合同档位表（新代码常量模块）**：六档（2019·服务、2019·代缴、2019·培训、2021-2022、2023·分校、2023·分店）。每档字段：档位 id、显示名、违约金率、必扣项清单（含仅分店的场地费）、各科考试费/补考费标准、实操单价表（按 C1/C2）、特征句列表、适用年份区间与网点类型。2021 与 2022 合并为一档。
- **档位识别**：输入（报名日期、网点类型、合同文本）→ 输出（档位、置信度、证据列表、候选列表）。年份+网点类型先收敛候选集，特征句匹配打分；文本文献与权威数据冲突时以告警呈现不静默采信。识别结果持久化在工单上，用户改档位走重算接口（缓存键随之变化）。
- **一套合同模型**：工单的合同集合字段由「单份 dict」升级为「按份类型分条」的结构，每份含：份类型（kind：服务/代缴/培训/单一培训）、档位、文件引用、提取文本（含来源与置信度）、分析结果。旧的单份结构按单条兼容读取。汇总器合并各份明细；培训费总额 = 各份手写总额之和；摘要条标注「已识别 N 份」。
- **提取管线复用**：每份文件沿用现有提取降级链（文本层 PDF → 视觉 LLM → 本地 OCR）。提取出的正文**随分析结果落库**（含来源与置信度），不再在结果中剔除——这是偏移量锚定的硬前提（ADR-0002）。
- **关键信息抽取（LLM prompt 升级）**：在现有输出 schema 基础上，要求每条扣费项附带**原文锚点短语**；手写金额字段附带位置描述。违约金率/考试费等印刷标准值不再要求 LLM 给出金额结论，只做与档位默认值的交叉校验。
- **偏移量锚定**：后端把锚点短语解析为正文字符区间 [start, end) 并连同条款号、页码一并落库；锚定失败的项标 `anchor_missing`，前端该条不显示定位按钮。锚点只对产生它的那份正文有效——重新提取正文必须重算锚点。
- **扣费计算引擎（纯函数）**：输入（档位、阶段、进度〔各科已考次数、审核学时〕、手写金额）→ 输出有序明细。规则：必扣项全扣；考试费/补考费仅计已考科目（已考次数 > 0），金额取档位标准；实操费 = 审核学时 × 档位单价；违约金 = 培训费总额 × 档位比例，恒排最后；**已受理（培训档）＝理论培训费视为已发生全额扣**；实操中另加已发生实操费。每条明细带置信来源（tier_default / ocr / manual / pending）。
- **金额置信度与闸门**：档位默认值=高置信；OCR 抽取=中置信；人工录入=高置信；缺失=pending。pending 项不计入应退合计；存在 pending 时费用方案不可确认、归档三闸拒绝（对接现有归档校验）。
- **预览 API**：读取分析结果时一并返回正文（含条款切分与页码映射）、锚点化明细、档位信息、原件清单。新增按页取图接口（仅扫描版 PDF 兜底）：页图缓存在以文件指纹为名的独立目录下，整目录 LRU 清理（上限常量），无碎片。
- **分析缓存键**：文件指纹 + 档位 + 进度哈希。任一变化即重算；重开命中即秒回。
- **前端预览组件（数据源无关）**：三栏 props 化（原件清单 / 结构化原文+锚点 / 明细列表），不感知数据来自下载还是上传。本期只接入上传件入口；下载件迁移是二期，本期不改动下载链路任何行为。中栏原件：照片直接显示、文本 PDF 浏览器端渲染、扫描 PDF 用页图接口。
- **静态资源**：新组件与样式按项目惯例登记版本号并进 importmap 自检（防止整站白屏——见项目记忆的 importmap 陷阱）。

## Testing Decisions

- **好测试的标准**：只断言外部可观察行为——给定合同文件与进度，输出的明细、金额、锚点区间、汇总与闸门状态是否正确；不测内部函数调用次数或私有结构。
- **接缝一（服务层，主战场）**：以「上传件分析管线」为唯一核心接缝：输入真实合同 fixture（由 `1合同种类/` 七份模板生成）+ 进度/网点上下文，断言六档矩阵——违约金三档比例、必扣 1000/1700 差异、考试费的已考门控、实操费封顶、待确认灰点、锚点区间落在正文正确位置。提取层用文本型 PDF fixture 走真实提取；LLM 路径以桩替换（现有合同测试同款做法）。
- **接缝二（HTTP 层，集成）**：用 Flask 测试客户端走 上传 → 分析 → 读取预览 → 改档位重算 → 归档闸门拒绝（存在 pending 时）全链路。
- **表驱动**：六档 × 关键场景（理论前/已受理/实操中/已考科目组合/金额缺失）用参数化用例覆盖，矩阵即验收标准。
- **回归护栏**：下载链路现有行为加最小护栏用例（下载件分析输出结构不变），保证「本期不碰下载链路」是可验证的承诺。
- **既有 prior art**：合同扣费规则测试、归档 API 测试、驾培跳过闸门测试（tests/ 目录均有同构先例，沿用其 fixture 与桩手法）。

## Out of Scope

- 下载件迁移到三栏预览组件（二期，组件已按数据源无关设计）。
- 缴费凭证附件入口（用户明确：2019 年不需要缴费凭证）。
- 档位规则的管理界面（先代码常量；出现「分店自调费率」需求再升级为配置表）。
- OCR 模型/识别率调优、合同模板新增支持（新增模板只需在档位表登记）。
- 移动端适配。

## Further Notes

- 2019 年三份合同甲乙方不同（服务合同甲方为总部），识别份类型时可用此差异做辅助特征，但不作为唯一判据。
- 术语与基数裁定（2026-09-01 拍板）：份类型术语见 `CONTEXT.md`「合同份」；多份并行时违约金基数 = 各份手写总额之和、代缴份不计入（ADR-0003）；新扣费引擎另起炉灶不继承 refund_engine 契约（ADR-0003）。
- 「已完成（含已开始）的考试科目」的用户裁定口径：考试费只看已考/已约考；「含已开始」仅影响实操培训费的「已产生」认定（Round 2 Q10）。
- 已受理阶段的口径修正（Round 3）：已受理＝科目一（理论培训）阶段，理论培训费视为已发生——不要按「理论培训前」处理。
- demo（`demo/contract-upload-parity-v1.html`）是版式的唯一权威参照；实现以它为像素基准，用户按轮迭代反馈。
- ⚠️ 工程红线（项目记忆）：`.scratch/` 被 git 跟踪禁止批量删；改前端必须 bump 静态版本号 + importmap 自检；标注工具会注入 `data-page-node-id` 破坏 Vue 模板，改 HTML 前先查残留。
