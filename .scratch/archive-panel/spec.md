# 方案 A 规格：网页内置归档面板

日期：2026-09-10　状态：**待用户审批**
上游：`.scratch/archive-panel/audit.md`（审计） / `.scratch/open-archive-diagnosis-20260901.md`（故障诊断）

---

## 1. 一句话目标

把「打开归档」从「尝试在我电脑上弹出资源管理器」改为「**在网页里把该学员归档夹的文件直接摊给用户**」——
零安装、零配置、**点了必有反应**，覆盖打印 / 转发 / 查看三类真实诉求。

## 2. 用户故事（验收基线）

| # | 场景 | 期望 |
|---|---|---|
| U1 | 列表里点某学员的归档按钮 | 弹出面板，列出该案件夹全部文件（名称/大小/修改时间） |
| U2 | 我只想要那份回复函 | 面板里直接点该文件 → 下载到本机「下载」目录 |
| U3 | 我想先看一眼合同 PDF 长什么样 | 点「预览」→ 新标签页内联打开（PDF/图片） |
| U4 | 该学员还没生成任何文档 | 面板显示明确文案：「该学员尚未生成登记表/回复函」，而不是空白或报错 |
| U5 | 归档共享盘没挂载 | 面板显示明确文案：「归档共享盘暂时不可用，请联系管理员」，**与 U4 区分** |
| U6 | 我在服务器本机（Mac）用 | 面板里额外出现「在服务器上打开文件夹」按钮（可选增强） |
| U7 | 我是 Windows 局域网客户端 | 不需要装任何东西，不需要浏览器授权，U1–U3 全部可用 |

> **已取消的用户故事（用户 2026-09-10 明确要求）**：~~「整个案卷打包成 zip 下载」~~
> 原话：**「不用这个 zip，用户需要哪个文件自己打开，自己下载就行，不要压缩打包」**
> → 面板不提供打包入口，只有单文件下载。「查看全部文件」的能力由面板列表本身承担。

## 3. 范围

### 3.1 做（In Scope）

**后端**
- `GET /api/tickets/<id>/archive-files` — **保持现有响应契约不变**（`{dir, files:[{name,size,mtime}]}`），避免连锁改动；追加字段用新增键，不改既有键。
- `GET /api/tickets/<id>/archive-files/download?name=` — 现状保留（单文件下载，方案 A 唯一的取文件途径）。
- **新增** `GET /api/tickets/<id>/archive-files/preview?name=` — PDF/图片内联；沿用 `app.py:5265-5290` 的白名单 + `mimetypes` 模式；**docx/其他一律不给内联**（返回 415，前端引导下载）。
- **错误分级**：`archive-files` 系列在 `root_unavailable` / `dir_missing` 时返回**结构化 code**（`{"success":false,"code":"...","errors":[...]}`），前端据此显示不同文案。
- `POST /open-archive` — 收敛为**仅本机可用**：非本机来源直接 403（不再返回 UNC、不再要求前端做 blur 猜测）。

**前端**
- 面板提升为主路径：`openArchive(t)` 直接开面板，不再先请求 `open-archive`。
- 面板重做：工具栏（复制路径 / 刷新 / 列表↔图标视图）+ 文件行（图标、名称、大小、时间、下载、预览）。**不设打包入口。**
- 错误态三分类渲染（U4 / U5 / 通用失败），每类给不同的行动指引。
- 入口文案与图标改为「查看归档文件 / `bi-files`」，`.row-open` 重命名（如 `.row-view-files`）。

### 3.2 不做（Out of Scope，防止范围蔓延）
- ❌ **ZIP 打包下载**（用户 2026-09-10 明确：不需要压缩打包，需要哪个文件自己下载）
- ❌ 多选批量下载（同理——"自己下载"即逐个下载）
- ❌ 修共享盘挂载逻辑（用户明确排除；只做错误提示分级）
- ❌ docx 服务端转 PDF（重依赖 LibreOffice）
- ❌ docx 前端渲染（需引入 mammoth 等 CDN 依赖，且中文字体走样风险高）
- ❌ 面板内上传 / 删除 / 重命名（归档区只读，写入仍走既有归档流程）
- ❌ 权限模型变更（沿用 `login_required`，不引入「只能看自己的工单」）
- ❌ 手机端专门适配（沿用现有响应式断点即可）
