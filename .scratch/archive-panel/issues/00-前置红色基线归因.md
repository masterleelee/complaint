## 根因 A（#1–#6）：测试打桩目标错误 → 归档路由读到了真实生产配置

### 证据（已用实验证实，非推断）

```
$ python -c "import config as C, app as A; print(A.load_config is C.load_config)"
True                                  # 初始同一对象
$ # patch 之后
C.load_config = lambda: {'archive_root': '/tmp/PROBE'}
A.load_config()  → /Volumes/File/综合办公室/内部共用/投诉文件/投诉处理系统   ← 仍读真实配置
C.load_config()  → /tmp/PROBE
```

**机理**：`app.py:32` 是 `from config import load_config, ...` —— **直接绑定**，导入时就把名字绑到了原函数对象上。
测试里写的 `monkeypatch.setattr(config_module, "load_config", ...)`（如 `tests/test_archive_api.py:121`）只改 `config` 模块的属性，**对 `app.load_config` 完全无效**。

于是 `app.py:3718-3726`：
```python
cfg = load_config()                       # ← 真实配置：/Volumes/File/...
root = str(body.get("archive_root") or "").strip()
if root: ...
else: root = cfg.get("archive_root", "案件归档")
case_dir, ... = build_archive_dir(ticket, root=root)   # ← 显式传 root，覆盖 service 层打桩
```
把真实路径显式传给 `build_archive_dir`，**连带让 `archive_service_module.load_config` 的打桩也失效**（那条打桩本身是对的，只是被 `root=` 绕过了）。

### 触发条件

`_normalize_archive_root` → `os.makedirs('/Volumes/File/...')` → `PermissionError: [Errno 13] Permission denied: '/Volumes/File'`
（`/Volumes` 归 `root:wheel 755`，普通用户无法创建；且此刻共享盘未挂载）

**即：这批归档测试从来没有真正隔离环境，其通过与否取决于共享盘是否挂载。**

### 附带暴露的数据卫生问题

由于打桩无效，这些测试在**共享盘挂载时会把测试用的 `登记表_src.docx` / `回复函_src.docx` 真实写入生产归档目录**（traceback 已证实它尝试的正是 `/Volumes/File/...`）。这是一个独立于本方案的问题，建议一并修掉。

### 修复方向（择一，属实现细节需审批）

- **(a) 改测试**：把打桩目标从 `config_module.load_config` 改为 `app_module.load_config`（最小改动，直击根因）；
- **(b) 改测试基建**：在 `tests/conftest.py` 加 autouse fixture，统一把 `app.load_config` / `archive_service.load_config` 指向临时目录，一次性根治同类问题（推荐——因为同类错误可能散落在其他测试里）；
- **(c) 改产品代码**：`app.py` 改为 `import config` + `config.load_config()`（让打桩天然生效）。**不推荐**：波及 9 处调用点，属范围蔓延。
