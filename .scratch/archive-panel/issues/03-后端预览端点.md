# ISS-AP-03 · 后端：归档文件内联预览

**Status:** done — 2026-09-10：新增 `GET /api/tickets/<id>/archive-files/preview`（`app.py`），
按扩展名白名单内联返回 PDF / 图片 / TXT，其余 415。全量回归 **659 passed / 0 failed**。
**Priority:** P1
**依赖:** ISS-AP-01（错误 code 约定）✅
**并行:** 与 ISS-AP-02 完全并行（02 已作废）

## 需求

U4：用户想先看一眼合同 PDF 或扫描件，不想先下载再打开。

## 改动点

1. `app.py` 新增路由：

```python
@app.route("/api/tickets/<ticket_id>/archive-files/preview")
@login_required
def api_tickets_archive_file_preview(ticket_id): ...
```

2. **安全口径直接沿用既有实现**（`app.py:5265-5290` `api_contract_preview`）：
   - `name` 参数与 download 端点同样做「basename 归一 + 原串比对」的穿越防护；
   - 最终路径必须落在 `resolve_case_dir()` 返回的 `case_dir` 内（用 `os.path.realpath` + 前缀比对，`archive_service._assert_within` 已有同款逻辑，可复用）。

3. **允许内联的类型白名单**（其余一律拒绝）：
   - `.pdf` → `application/pdf`
   - `.png` `.jpg` `.jpeg` `.gif` `.webp` `.bmp` → 对应 `image/*`
   - `.txt` → `text/plain; charset=utf-8`
   - **`.docx` / `.doc` 不在白名单** → 返回 `415` + `{"success":false,"error":"该类型不支持在线预览，请下载后打开"}`
   - 用**扩展名白名单**判定，不靠 `mimetypes.guess_type`（后者对未知类型返回 None 且可能给出 `application/octet-stream` 而被误放行）。

4. 响应：`send_file(fp, mimetype=..., as_attachment=False)`；补 `Content-Disposition: inline`（Flask 默认行为，需断言）。

## 验收标准

- [x] PDF → 200 + `Content-Type: application/pdf` + `Content-Disposition` 含 `inline`
- [x] PNG → 200 + `image/png`
- [x] TXT → 200 + `text/plain; charset=utf-8`
- [x] DOCX → 415 + 可读文案
- [x] 未知扩展名 → 415（不得因 mimetype 猜测兜底而被放行）
- [x] `name=../../etc/passwd` → 400（穿越）
- [x] `name` 指向 `case_dir` 之外的绝对路径 → **400**（见下行修正）
- [x] 文件不存在 → 404；工单不存在 → 404
- [x] 夹子缺失 / 根不可用 → 对应 code（同 ISS-AP-01）

## 实现后回写（code-review 双轴结论）

**AC#7 原本字面未满足**：初版把 `name` 先 `basename` 归一，导致裸 `/etc/passwd.pdf`
被归一成 `passwd.pdf` 后在案件夹内去找 —— 安全（拿不到夹外文件），但返回 415/404
而非 AC 要求的 400/403。**已改为：文件名校验先于扩展名白名单**，绝对路径一律 400。

**顺带修掉的同源缺口（Standards 轴指出）**：原文声称「安全口径与 download 完全一致」，
实际 download **没有** realpath 越界校验 —— 案件夹内一个指向夹外的软链即可让 download
外泄文件。已抽出服务层公开 helper 供两条链路共用：

| helper（`services/archive_service.py`） | 职责 |
|---|---|
| `is_plain_file_name(name)` | 纯文件名判据（非空、非 `.`/`..`、无路径分隔符） |
| `safe_member_path(case_dir, name)` | 纯文件名 → 夹内安全绝对路径；名字非法**或** realpath 越界（含软链绕路）→ `None` |

由此 `app.py` 不再导入私有的 `_assert_within`（原先的跨层私有耦合一并消除）。

**另一个实测发现的缺陷**：`.txt` 初版 mimetype 写成 `text/plain; charset=utf-8`，
而 Flask 对 `text/*` 会**自动追加** charset → 响应头成了
`text/plain; charset=utf-8; charset=utf-8`（charset 重复两次）。已改为只写
`text/plain`，并在测试中断言 `Content-Type == "text/plain; charset=utf-8"`
且 `count("charset") == 1` 防回归。

**新增测试**：`tests/test_archive_preview_api.py`（17 例）、`tests/test_archive_service.py`
新增 `TestIsPlainFileName` / `TestSafeMemberPath` 两个类（表驱动 + 软链越界，该文件合计 34 例）
以及 `tests/test_archive_files_api.py` 追加 download 的绝对路径与软链两例（该文件合计 15 例）。
