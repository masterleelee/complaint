# ISS-AP-01 · 后端：归档面板错误分级（契约冻结）

**Status:** done — 2026-09-10：`_err_resolved()`（`app.py:3847`）统一映射 4 处失败分支；`resolve_case_dir()` 增 `message`/`detail`（`code` 值未改）。全量回归 **659 passed / 0 failed**。
**Priority:** P0（阻塞后续全部前端工作）
**依赖:** 无（本单先做，产出契约给 02/03/04 用）
**并行:** 可与 02/03 并行前的唯一前置

## 现象 / 需求

现在 `archive-files` 系列失败时只返回 `{"success":false,"errors":[...]}`，前端无法区分两种完全不同的原因：

- `root_unavailable`：归档共享盘未挂载 / 配置不可用 → **用户无能为力，要找管理员**
- `dir_missing`：该学员尚未生成登记表/回复函 → **用户自己能解决（去生成文档）**

混在一条提示里，用户看到的是「无法创建归档根目录…Permission denied」（程序员语言），既看不懂又误导。

## 改动点

1. `app.py` 的 `api_tickets_archive_files`（L3942-3976）、`api_tickets_archive_file_download`（L3979-4005）：
   失败分支统一返回 `jsonify({"success": False, "code": resolved["code"], "errors": [...]}), status`，
   其中 `code ∈ {"root_unavailable","dir_missing"}`，status 沿用现有映射 `{root_unavailable:400, dir_missing:404}`。
   - **注意**：`_err()` 目前不支持带 code（`app.py:217`），本单**不要改 `_err` 的签名**（全局 80+ 处调用），
     在这两个路由里直接 `jsonify` 构造，或新增一个局部 helper `_err_code(msg, code, status)`。
2. `services/archive_service.py` 的 `resolve_case_dir()`：**返回的 `code` 值不加不改**
   （`root_unavailable` / `dir_missing` 已是所需值），本单只是把它透传到 HTTP 层。
   ⚠️ 原文此处与第 3 条「文案分级放在 `resolve_case_dir` 内部更合适」自相矛盾
   （code-review Spec 轴指出）。**以第 3 条为准**：函数内新增了 `message` / `detail`
   两个键，`code` 取值保持不变。
3. 错误文案分级（放在 `archive_service.py` 的 `resolve_case_dir` 内部更合适，前端只做展示）：
   - `root_unavailable` → 「归档根目录不可用：共享盘可能未挂载或当前路径无权限，请联系管理员，或稍后重试」
   - `dir_missing` → 「案件归档夹不存在：该学员尚未生成投诉登记表/回复函，请先在工单里生成后再查看」
   - 保留原始技术细节便于排查，但前端只展示人话。

## 最终契约（实现后回写，前端按此对接）

```jsonc
// 失败响应（4 个端点一致：archive-files / archive-files/download /
//           archive-files/preview / open-archive）
{
  "success": false,
  "code": "root_unavailable" | "dir_missing" | "launch_failed",
  "errors": [ "<人话，单元素>" ],   // 前端直接展示 errors[0]
  "message": "<同 errors[0]>",      // 与 errors[0] 同值，语义化别名
  "detail": "<技术细节，仅排查用，不在界面展示>"
}
```

**与原文第 3 条的偏离（已裁定，勿回退）**：原文写「保留原始技术细节在 `errors` 数组里（不删）」，
实现改为放进独立的 `detail` 键。理由有二：

1. `errors` 在多处被断言 `len(errors) == 1`（`test_open_archive_api.py::test_open_case_dir_root_none_uses_config`），
   往里塞第二条会直接打红既有用例；
2. `errors[0]` 就是前端要展示的那一句，混入 `Permission denied` 等于把程序员语言甩给用户，
   与本节「用户看不懂又误导」的立单动机相悖。

`detail` 里的技术细节**没有丢失**，排查体验不变。

- [x] `download` 与 `preview`（ZIP 已作废）共用同一套 code 语义——两者共用 `_err_resolved()`

- [x] 新增用例：两个 code 各至少 1 例（list / download / preview 三个端点 × 两个 code，共 6 例，

## 风险

- **中**：改动会触碰既有 9 例测试的断言（错误体从 `error` 键变成 `code`+`errors`）。必须先跑一遍基线测试确认现状，再改。
- **低**：`_err()` 不动 → 无全局连锁。
