**硬指标**：`pytest tests/ -v` **0 failed / 0 error**；用例总数变化必须与上表预期**逐条对得上**（多删或少删都是问题）。

### L2 契约层（防连锁破坏）

- `GET /archive-files` 改动前后 JSON 做 **键级 diff**：既有键 `success/data/dir/files[name,size,mtime]` **必须键名与类型完全一致**，只允许新增键。
- 对消费方做反向引用检查：`grep -rn "archive-files" static/ templates/ tests/` → 确认无遗漏调用方。

### L3 浏览器 E2E（agent-browser）

采用**不顶号的登录态方案**（`tests/` 或 memory 中的既有做法：Flask `test_client` + `session_transaction` 伪造 session → 从 `Set-Cookie` 解析 → `agent-browser cookies set`），避免踢掉用户浏览器会话。

| # | 步骤 | 断言 |
|---|---|---|
| E1 | 打开投诉列表 → 点某案归档按钮 | 面板 `display` 非 none；`tbody tr` 行数 == 接口返回文件数 |
| E2 | 点某文件「下载」 | 产生 `/archive-files/download?name=` 请求且状态 200 |
| E3 | 点「打包下载」 | 产生 `/archive-files/zip` 请求且 `Content-Type: application/zip` |
| E4 | 点 PDF「预览」 | 新开标签且 200（或断言 `window.open` 被调用） |
| E5 | 关闭面板 → 打开另一工单 | 文件列表已刷新，不含上一工单数据 |
| E6 | 全程 | `agent-browser errors` 与 `agent-browser console` **均为空** |

> 注意（项目既有坑）：`snapshot`/`screenshot` 常返回空白，**用 `eval` 做 DOM 断言**；`eval` 不支持顶层 return，须包成 `(function(){...})()`。
> 收尾必须 `agent-browser close`。

### L4 故障注入（验证"必须有反应"）

| 注入 | 手段 | 期望 |
|---|---|---|
| 归档盘未挂载 | monkeypatch `resolve_case_dir` 返回 `root_unavailable` | 面板显示「共享盘暂时不可用，请联系管理员」，**不是**空白也不是"新功能坏了" |
| 学员无文档 | 指向不存在的案件夹 | 显示「尚未生成登记表/回复函，请先生成」 |
| 接口 500 | mock 返回 500 | 显示通用失败 + 可重试 |

### L5 性能

- 4 文件案件夹：`/archive-files` < 300ms、`/zip` < 1s、`/preview` < 500ms（本机实测，非挂载盘时另测）。
- 用 `time` 或 pytest 的耗时输出记录，存入 `evidence/`。

### L6 真机验收（HITL，不可省）

| 环境 | 验证 |
|---|---|
| 服务器本机（Mac） | 面板 U1–U4 + 「在服务器上打开文件夹」（若 D2=b） |
| **局域网 Windows 客户端（零安装）** | U1–U4 全部走通 —— **这是方案 A 的唯一存在理由，必须实测** |
| 归档盘未挂载状态 | 验证 L4 的两条文案在真实环境下的表现 |
