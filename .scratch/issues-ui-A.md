## ISS-C-A01 · P1 · 建案时手工填写的手机号丢失

- **页面**：新增投诉（intake）
- **现象**：表单填写 身份证号=110101199003070011、手机号=13800000000、处理人=QA-UI-A，点击「查询三系统并建案」。三系统查无此人仍正常建案，但工单 `phone` 字段落库为空串。
- **预期**：学员未命中时至少应保留用户手工输入的手机号。
- **复现步骤**：
  1. 打开 新增投诉 页
  2. 身份证号填一个校验位合法但三系统不存在的号码（如 110101199003070011），手机号填任意11位
  3. 点击「查询三系统并建案」
  4. 查库：`SELECT phone FROM complaint_tickets WHERE id_card='…'` → 结果为 ''
- **证据**：
  - 工单 abcac116-f65f-4e6d-ab8c-fb5f800a7826（phone=''、handler_name='QA-UI-A' 可证为本次提交）
  - 截图 a1920-05-workbench-after-intake.png（建案后工作台，学员档案手机号缺失）
- **根因定位**：`static/js/composables/useComplaint.js` queryAll() 构造 payload（约 L417–427）时按身份证查询分支只写 `payload.id_card = idToQuery`，未携带 `payload.phone = rawPhone`；后端 `_persist_query_result`（app.py:455）`"phone": phone or result.get("phone","")` 收到空 → 存空。
- **修复建议**：payload 中增加一行 `phone: rawPhone,`（后端已兼容）。
- **级别理由**：工单核心联系字段静默丢失，影响后续回访/沟通闭环 → P1。

## ISS-C-A02 · P2 · 侧栏「学员信息」命名与实际内容不符

- **页面**：全局侧边栏
- **现象**：「学员信息」按钮进入的是案件闭环工作台（view='workbench'，含扣费/回复函/归档全流程），并非学员信息页；初用者会误判导航失效。
- **证据**：templates/index.html:378 nav 定义；a1920-05 / a1920-08 截图对比。
- **建议**：更名「案件工作台」或拆分真实学员档案页；纯文案改动。
- **级别理由**：无功能损害，属信息架构歧义 → P2。

## ISS-C-A03 · P2 · 查询失败仍自动建案并跳转工作台（设计确认项）

- **页面**：新增投诉
- **现象**：三系统返回"查无此人"（错误提示已出）后，流程继续创建空学员工单并自动跳入工作台。提示语"请确认是否正确"暗示应修正重试，但系统已落库，易产生垃圾工单。
- **证据**：QA-FEE 流程截图 a1920-05（待处理工单、姓名/档案全空）；DB 中 abcac116 记录。
- **说明**：UI 文案"建案后立即计入统计"表明投诉登记与学员查询解耦可能是有意设计；**请 lead/Product 确认预期行为**。若确认为设计，本条关闭；若非，建议改为失败时停留当前页允许修正。
- **级别理由**：潜在垃圾数据源 + 提示与行为矛盾，但不破坏现有功能 → P2（待确认）。
