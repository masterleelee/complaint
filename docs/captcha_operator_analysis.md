# 东莞驾培验证码 运算符识别分析与校准

> 沉淀自 2026-08-21 的 80 张人工标注样本。后续若要复标，流程见末尾。

## 背景
- 东莞驾培（`https://www.guanjiaxie.com:8089`）登录用 RuoYi 算术验证码：`数字 运算符 数字 = ?`，单字符操作数、运算符为 `+ - * /` 之一。
- 识别引擎为 `ddddocr` 默认**通用 OCR 模型**（非验证码专用，未下载任何额外模型）。
- 验证码**单次有效**：每次登录尝试仅 1 次猜测机会（错误后服务端作废答案，错误提示统一为 `验证码错误`，有迷惑性），因此单张识别率决定整批成功率上限。

## 标注方法
1. `python scripts/captcha_labeler.py fetch` 下载 80 张到 `tmp/captcha_samples/`，生成 `review.html`。
2. 人工在浏览器逐张点选 `+ - * /`，导出 `labels.json` 覆盖原文件。
3. `python scripts/captcha_labeler.py summarize` 重新 OCR 同批图片，对照真值输出混淆矩阵。

## 真值分布（80 张）
`+` 35 / `-` 24 / `*` 16 / `/` 5

## OCR字符 -> 真运算符 混淆矩阵（80 张）
```
''         -> -  x13        (运算符被完全丢弃)
't'        -> +  x8         (注：t 主要是 +，不是 -)
''         -> +  x6
'+a'       -> +  x5         (a 是 =/? 后缀噪声)
'-'        -> -  x4
'*'        -> *  x4
'a'        -> -  x4         (a 噪声)
't'        -> *  x4
'*a'       -> *  x3
'+'        -> +  x3
'ya'       -> +  x3
'x'        -> +  x2         (x 主要是 +)
'ta'       -> +  x2
'ja'       -> +  x2
'y'        -> -  x2
'x'        -> -  x1
'ta'       -> *  x1
'+ja'      -> +  x1
''         -> /  x1
'a'        -> /  x1
'kkx'      -> *  x1
'y'        -> +  x1
'xa'       -> *  x1
'/'        -> /  x1
'tja'      -> *  x1
'ly'       -> /  x1         (l 是 ÷ 除号)
'lx'       -> /  x1
'*tx'      -> *  x1
'yy'       -> +  x1
'a'        -> +  x1
```

## 关键结论
1. **`a` 是 `=`/`?` 后缀噪声**，被 ddddocr 读成字母 `a` 并混入运算符判断（出现在 `+a`/`*a`/`ta`/`ya`/`ja`/`xa`/`tja` 等）。必须**剔除**。
2. **`l` 是 `÷` 除号**：所有 `/` 样本都被读成 `l`/`ly`/`lx`。原 `_op_map` 未收录 `l`，导致 `/` 识别率长期为 **0%**。映射 `l -> /` 即可恢复。
3. **旧 `op_map` 存在系统性偏乘号化**：原把 `t->-`、`x/h/k/y->*`，但实测 `t` 多为 `+`（8:4）、`x` 多为 `+`（2:1）、`y` 多为 `-`（2:1）。这正是此前整批登录成功率里 `*` 占比虚高、`+`/`/` 偏低的根因。
4. **干净符号读取仅约 15%**，多数运算符被读成字母；单张识别率受限于此，故**提高重试次数**是最稳的兜底杠杆。

## 校准后的 `_op_map`（`crawlers/driving.py`）
```python
_op_map = {
    't': '+', 'x': '+', 'y': '-', 'i': '+', 'j': '+',   # 校准：t/x 多读成 +，y 多读成 -
    'h': '*', 'k': '*',                                  # 样本未观测，保留原 * 映射
    'l': '/',                                            # 除号 ÷ 被读成 l
}
_NOISE = set('a')  # =/? 后缀被读成 a，剔除
```
- `LOGIN_MAX_ATTEMPTS` 3 -> 6。
- 解析时先剔除 `a` 噪声再取运算符字符，沿用"严格三连 -> 运算符回退 -> 穷举 4 运算符取 0~81 首有效"兜底链。

## 验证（2026-08-21，线上实测）
- 连续 30 次全新登录：**30/30 = 100%**，耗时约 19s。
- 历史对照（旧代码 + 旧 remap + 3 次重试）：整批 92.4%、单张约 58%（由失败率反推）。

## 复标流程
1. `python scripts/captcha_labeler.py fetch` （默认 80 张，可在脚本改 `N`）。
2. 浏览器打开 `tmp/captcha_samples/review.html` 逐张点选，导出 `labels.json` 覆盖 `tmp/captcha_samples/labels.json`。
3. `python scripts/captcha_labeler.py summarize` 查看新混淆矩阵；若与本文冲突，以新数据更新上方 `_op_map`。
4. 跑线上登录基准复验：循环调用 `DrivingCrawler()._do_login()` 统计成功率。

- `/` 样本仅 5 张，置信度相对低；逻辑上 `l->/` 确凿且已通过实测，暂不再补标。若后续上线出现除号相关失败，优先回灌此类样本。
