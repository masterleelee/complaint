# 账号体系使用说明（v1）

## 1. 概述

本系统从 v3 起引入账号体系。所有学员投诉工单的处理人由具体账号绑定，统计与责任追溯更准确。

## 2. 角色

| 角色 | 权限 |
|---|---|
| **管理员 (admin)** | 全权限：增删改查用户、转办、配置系统设置、看所有数据 |
| **投诉专员 (handler)** | 看全表、受理/转办/归档/查看学员信息/看统计 |
| **只读审计 (viewer)** | 看全表；**所有写操作（保存/转办/删除/确认费用/归档）置灰** |

> 三种角色看的数据范围一致（题目"所有人都看全表"），仅写权限不同。

## 3. 默认账号

首次启动系统自动创建：

| 用户名 | 初始密码 | 角色 | 真实姓名 |
|---|---|---|---|
| `admin` | `admin` | 管理员 | 系统管理员 |

**首次登录后请立刻修改密码**（右上角"修改密码"或系统设置→我的资料→修改密码）。

## 4. 登录 / 退出

- 访问 http://localhost:5003/ 跳登录页
- 输用户名 + 密码登录（默认 admin/admin）
- 右上角"系统管理员 (管理员)"显示当前账号
- 8 小时 session 自动过期；或左下角"退出登录"

## 5. 多人协作 & 踢人

同一账号在 A 电脑登录后，再在 B 电脑登录同一账号——A 那边下次操作 API 时会收到 401，前端自动跳登录页。

这是为了防止"账号借出去"时旧 session 继续操作。**session 失效后用户只需重新登录**。

## 6. 创建 / 管理账号（仅管理员）

进入"系统设置"页面 → 下方"用户管理"卡：

| 操作 | 说明 |
|---|---|
| **新增用户** | 输用户名、真实姓名、初始密码（建议 123456，让对方首次登录后改）、角色、手机号 |
| **编辑** | 改真实姓名/手机号/角色。**用户名不可改**（登录凭证） |
| **重置密码** | 直接覆盖为新密码，不需要原密码。适合对方忘了密码 |
| **停用 / 启用** | 软删除。停用后账号无法登录，列表中依然显示（"已停用"） |

**admin 不能停用自己**——避免误操作把自己锁出去。

## 7. 处理人字段（核心特性）

### 新建投诉时

打开"新增投诉"页面，处理人字段是**下拉选择**，不是手填：

- 默认值 = **当前登录用户**
- 可改成其他 admin / 投诉专员
- 排除 viewer 和停用账号

提交时同时存 `handler_user_id`（账号 id）+ `handler_name`（冗余展示）。

### 投诉列表的"处理人"列

- 优先显示**真实姓名**（按 `handler_user_id` 查 user 表）
- 旧工单没有 `handler_user_id` 时显示**原 `handler_name` + 灰色"（未关联账号）"**后缀

### 批量转办

在投诉列表选若干行 →"批量转办" → 选接收人（账号下拉）→ 确认。

**转办是把 `handler_user_id` 和 `handler_name` 同时改掉**。前台筛选下拉也变成"按账号"过滤。

## 8. 老数据迁移 / 历史处理人映射

旧工单里 `handler_name` 是手填字符串（如"李老师"），新系统不识别为系统账号。要让它显示为某人的真实姓名，需要 admin 在系统设置里建映射：

### 自动迁移（启动时）

- 应用启动时跑 `migrate_handler_names_to_user()`：扫所有 `handler_user_id IS NULL` 且 `handler_name` 非空的工单，按 `handler_name_aliases` 表查映射并回写
- 已经配过 alias 的工单会自动得到 `handler_user_id`

### 手动配置别名（仅管理员）

系统设置 →"历史处理人映射"卡：

1. 上方黄色提示条列出所有"未映射"的历史处理人（按出现次数排序），点"「李老师」→ 绑定账号"快捷按钮
2. 或点"新增映射"手动输老名+选账号
3. 提交后**自动回写**所有用这个老名的工单（`handler_user_id` 被填上）

### 删除别名

点 alias 行的"删除"按钮 → 相关工单的 `handler_user_id` 自动回滚为 NULL（保留原 `handler_name`），重新显示为"未关联账号"。

## 9. 修改自己密码

- 系统设置 → 我的资料 → 修改密码
- 要原密码（防 hijack）
- 改密后**当前 session 立即失效**，需要重新登录

## 10. 常见问题

### Q: 我把 admin 密码忘了怎么办？
A: 在项目根目录命令行执行：
```python
python3 -c "
import database
from werkzeug.security import generate_password_hash
import sqlite3
conn = sqlite3.connect(str(database.DB_PATH))
conn.execute('UPDATE users SET password_hash=? WHERE username=\"admin\"', (generate_password_hash('新密码'),))
conn.commit()
"
```

### Q: 启动报错"port 5003 in use"
A: 旧的 Flask 进程没退：`lsof -i :5003` 找 PID → `kill <PID>`。

### Q: viewer 改不了东西？
A: 设计如此。viewer 是只读审计账号。联系 admin 把你改成 handler。

### Q: 转给别人后工单列表没变化？
A: 切换到"投诉列表"会重新拉取（已加 watch）。或在工单列表内手动刷新。

### Q: 登录后跳回登录页？
A: 8 小时 session 过期或被同账号他人登录踢掉。重新登录。

## 11. 安全注意事项

- 部署到生产前 **必须**通过环境变量设置 `FLASK_SECRET_KEY`（不设置则每次启动随机生成，会让所有 session 失效）
- 部署后立刻改 admin 密码
- 共享电脑登录后请主动点"退出登录"（不然 8 小时内别人可继续用你的 session）
