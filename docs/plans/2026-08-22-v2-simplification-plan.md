# v2 需求收敛与功能删减计划

> 版本：2026-08-22 · 由 grill-me 需求访谈产出（12 项决议全部经用户确认）
> 目标：把系统收敛为「查询学员信息 → 扣费明细 → 回复函（按需）→ 统计看板 → 归档」的直线流程。
> 本文档优先级高于 `docs/PRD.md` 与 `docs/acceptance/v1-requirements-matrix.md` 中与之冲突的条目。

---

## 1. v2 核心流程（六步主干）

```
① 受理登记 ──► ② 三系统查询 ──► ③ 扣费明细表 ──► ④ 回复函(可选) ──► ⑤ 处理情况+配合度 ──► ⑥ 归档
   │              │                │                  │                  │                    │
   提取身份证/手机号   身份证优先手机号兜底    屏显可编辑+Excel      单模板自动填充        归档闸门两要素      三件套写入本地档案
   投诉类型必填(默认退学退费)             AI失败手动录入         不写不影响流程                          [撤诉]按钮任意环节可用
   生成登记表.docx                                                              │
   ◄──────────────────── 受理即入统计，全程可见于看板 ────────────────────►
```

撤诉例外：任意状态（含已归档）可点「标记撤诉」；撤诉 ≠ 有效投诉；案件记录与档案永久保留。

## 2. 需求决议清单

| # | 决议点 | 结论 |
|---|---|---|
| D01 | 费用方案三态版本管理 | **简化**。删除 AI草案→阶段性→正式 流转、不可变快照、重开留痕。只留一张可直接编辑的扣费明细表 |
| D02 | 多轮结构化沟通记录 | **删除**。替换为单个「处理情况」自由文本框，归档时填写 |
| D03 | 六类固定最终结果 | **取消**。不再强制选择；结果体现在处理情况描述中 |
| D04 | 归档闸门 | **三条件**：①处理情况已填 ②配合度已评 ③扣费明细表已确认。回复函非必需 |
| D05 | 扣费明细表形态 | 屏显可编辑表格（项目/金额/扣费依据）+ 一键导出 Excel |
| D06 | 合同缺失兜底 | AI 提取失败或无合同时，处理人手动增删明细行，流程永不卡死 |
| D07 | 文档三件套 | ①投诉登记表.docx——受理时生成 ②扣费明细表.xlsx——归档必选 ③投诉回复函.docx——按需 |
| D08 | 统计入账时机 | 受理即入账；写函与否不影响计数；在途/已归档在看板区分 |
| D09 | 看板模块 | 全保留五项：单位排行、时间趋势、配合度汇总、处理时长、百车投诉率 |
| D10 | 归档目录 | `根目录/分校或分店/代号-全称/2026-05-10_姓名_身份证_代号/` 一案一夹；日期补零 |
| D11 | 命名日期含义 | 用受理日期（投诉进来那天），非归档日期 |
| D12 | 飞书归档 | 整体删除 |
| D13 | 回复函机制 | 单模板+学员状态与金额自动填充；模板管理精简保留（上传/设默认） |
| D14 | 边角功能 | 删登记表 LLM 总结、删操作日志页；保留工单 Excel 导出 |
| D15 | 撤诉机制 | 案件详情页常驻「标记撤诉」按钮；任意状态可点；统计自动从有效投诉移入撤诉列；已归档的自动向原档案夹补撤诉说明并更新登记表 |
| D16 | 投诉类型 | 必填项，受理时默认「退学退费」；看板出图；明细列表可见可筛选 |

## 6. 归档命名规范（定稿）

```
{归档根目录}/
  分校/
    总-东坑总校/
      2026-05-10_张雅婷_110101199003070011_总/
        2026-05-10_张雅婷_110101199003070011_总_投诉登记表.docx
        2026-05-10_张雅婷_110101199003070011_总_扣费明细表.xlsx
        2026-05-10_张雅婷_110101199003070011_总_投诉回复函.docx   ← 仅当生成了回复函
  分店/
    权-殷焕权/
      ...
```

- 日期 = 受理日期，格式 `YYYY-MM-DD`（补零，保证排序即时间序）。
- 案件夹名 = `{日期}_{姓名}_身份证_{代号}`；文件名 = 案件夹名 + `_文档类型`。
- 身份证未知时以实际采集到的线索占位并标记 `_待补`。

## 8. 成功标准（整体验收）

1. 一个常规案件从受理到归档，核心操作不超过 4 个页面、无强制无效步骤。
2. 归档产物严格等于三件套（回复函缺席合法），目录命名 100% 符合第 6 节规范。
3. 撤诉在任何状态下一键完成，统计数字与档案文件自动一致，无需人工改文件。
4. 全量自动化测试通过；被删功能无死代码、无死路由、无死入口残留。
