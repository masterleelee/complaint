# v1 投诉案件闭环工作台验收矩阵

> 本文件与 `docs/PRD.md` 共同构成 v1 验收基线。发生冲突时，优先级为：用户已确认业务决策、`docs/PRD.md`、本文件、`MEMORY.md`、现有代码、旧 DRD 与历史计划。

## 产品边界

v1 解决投诉案件从受理到归档的信息闭环，不承担退款付款、退学申请表签字流转或账号权限管理。

标准流程：

1. 投诉受理与分类
2. 身份证号/手机号线索识别
3. 三系统查询
4. 合同获取或上传
5. 合同字段提取与规则扣费
6. 人工确认阶段性或正式费用方案
7. 多轮沟通记录
8. 最终结果归档
9. 按需生成回复函
10. 统计分析

最终结果固定为：

- 投诉撤销
- 同意合同扣费
- 不同意合同扣费但协商一致
- 不同意合同扣费且协商失败
- 无法联系
- 继续培训/转校

- 两页纸质合同以同一案件上传：保留 2 份原件、2 份分析副本和 1 份合并预览，文件清单与工单绑定且不覆盖历史证据。

- 人工复核字段会在服务端重建 canonical contract set，客户端金额与扣费明细不能覆盖服务端计算。
- 匿名确定性场景（实缴 3680 元、明确零培训/零考试进度）验证：固定扣费 1000 元、20% 违约金 736 元、合计扣费 1736 元、应退 1944 元。该场景只验证规则引擎，不代表真实学员结论。
- 浏览器桌面端验证历史恢复和费用方案重开；手机 390×844 验证退费分析核心控件与布局。全量自动化测试为 289 项通过。
- 真实案件仍缺实际已交金额、有效培训学时及考试/补考发生次数，因此业务闭环停在人工复核，不允许正式确认、对外沟通或归档。

## v1 明确排除

| 排除项 | v1 边界 |
|---|---|
| 退款执行 | 只计算和确认应退金额，不发起或跟踪付款 |
| 退学申请表管理 | 不管理模板、签字件、审批和回收 |
| 账号与权限 | 不建设登录账号、角色和权限体系 |
| 完整投诉内容 AI 提取 | 自动识别只提取身份证号和手机号；投诉事实由处理人登记 |
| 自动回复函 | 回复函按需生成，不是所有案件的默认终点 |
| 飞书强制归档 | 飞书为可选输出，不作为完结闸门 |
| 退费金额统计 | 金额只用于案件详情、文档和归档；看板不做分校/分店金额排行 |

## 最终验收门槛

只有同时满足以下条件，才能宣布 v1 完成：

1. 本矩阵无 `未覆盖` 项。
2. 表格中标记为 `P0` 的项目全部具有自动化测试和至少一条完整案件端到端测试。
3. `合同文件/` 中每个真实样本都有已确认期望值或被标记为不可判定。
4. 三系统完成正常、无记录、部分失败和超时验收。
5. 桌面与手机完成受理、合同、费用、沟通、归档、回复函和历史恢复验收。
6. 全量测试、Python 编译和 JavaScript 语法检查通过。
